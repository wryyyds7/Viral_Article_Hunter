## 一、通用约定

### 1.1 Base URL

```
生产环境：https://api.hotcontent-hunter.com/v1
开发环境：http://localhost:8080/v1
```

### 1.2 协议与格式

| 项目 | 规范 |
|------|------|
| 协议 | HTTPS（生产）/ HTTP（开发） |
| 请求格式 | `Content-Type: application/json` |
| 响应格式 | `Content-Type: application/json; charset=utf-8` |
| 字符编码 | UTF-8 |
| 时间格式 | ISO 8601：`2026-06-04T11:50:00+08:00` |
| 日期格式 | `YYYY-MM-DD` |
| 时区 | Asia/Shanghai (UTC+8) |

### 1.3 认证方式

| 方式 | 说明 |
|------|------|
| Bearer Token | 请求头 `Authorization: Bearer <token>` |
| Token获取 | 首次使用时由系统自动分配，存储在本地 |

> MVP阶段采用简单的Token认证，后续版本可接入OAuth2。

## 二、统一响应格式

### 2.1 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

### 2.2 列表响应（带分页）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [ ... ],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 156,
      "total_pages": 8
    }
  }
}
```

### 2.3 错误响应

```json
{
  "code": 40001,
  "message": "参数校验失败",
  "errors": [
    {
      "field": "keyword",
      "message": "关键词不能为空"
    }
  ]
}
```

## 三、错误码规范

### 3.1 错误码结构

```
[HTTP状态码][业务模块][错误序号]
示例：40001 = HTTP 400 + 模块0(通用) + 序号01
```

### 3.2 通用错误码

| 错误码 | HTTP状态码 | 说明 | 前端处理 |
|--------|-----------|------|----------|
| 0 | 200 | 成功 | 正常处理 |
| 40001 | 400 | 参数校验失败 | 展示具体字段错误 |
| 40002 | 400 | 请求体格式错误 | 提示"请求格式有误" |
| 40101 | 401 | 未认证（Token缺失） | 跳转登录/配置页 |
| 40102 | 401 | Token无效或过期 | 重新获取Token |
| 40301 | 403 | 无权限访问 | 提示"无权限" |
| 40401 | 404 | 资源不存在 | 提示"内容不存在" |
| 42901 | 429 | 请求频率超限 | 提示"操作过于频繁，请稍后" |
| 50001 | 500 | 服务器内部错误 | 提示"服务异常，请稍后重试" |
| 50002 | 502 | 上游服务不可用 | 提示"服务暂时不可用" |
| 50003 | 504 | 请求超时 | 提示"请求超时，请重试" |

### 3.3 业务模块错误码

| 模块 | 错误码前缀 | 说明 |
|------|-----------|------|
| 通用 | 0xx | 40001-40099 |
| 采集 | 1xx | 40101-40199 |
| 分析 | 2xx | 40201-40299 |
| 改写 | 3xx | 40301-40399 |
| 素材库 | 4xx | 40401-40499 |
| 看板 | 5xx | 40501-40599 |
| 设置 | 6xx | 40601-40699 |

### 3.4 采集模块错误码

| 错误码 | HTTP状态码 | 说明 |
|--------|-----------|------|
| 40101 | 400 | 关键词为空 |
| 40102 | 400 | 平台参数无效 |
| 40103 | 400 | 时间范围无效 |
| 40104 | 403 | API Key未配置 |
| 40105 | 403 | API Key无效 |
| 40106 | 502 | 采集源服务不可用 |
| 40107 | 504 | 采集超时 |

### 3.5 改写模块错误码

| 错误码 | HTTP状态码 | 说明 |
|--------|-----------|------|
| 40301 | 400 | 未选择素材 |
| 40302 | 400 | 未选择目标平台 |
| 40303 | 400 | 素材不存在 |
| 40304 | 400 | 参数超出范围 |
| 40305 | 403 | LLM API Key未配置 |
| 40306 | 502 | LLM服务不可用 |
| 40307 | 504 | 生成超时 |
| 40308 | 500 | 生成内容审核不通过 |

## 四、分页规范

### 4.1 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| page | integer | 否 | 1 | 页码，从1开始 |
| page_size | integer | 否 | 20 | 每页条数，范围1-50 |

### 4.2 响应字段

| 字段 | 类型 | 说明 |
|------|------|------|
| pagination.page | integer | 当前页码 |
| pagination.page_size | integer | 每页条数 |
| pagination.total | integer | 总记录数 |
| pagination.total_pages | integer | 总页数 |

## 八、请求限流

| 接口类型 | 限流规则 |
|----------|----------|
| 采集接口 | 同一用户 10次/分钟 |
| 改写接口 | 同一用户 5次/分钟 |
| 分析接口 | 同一用户 20次/分钟 |
| 查询接口 | 同一用户 60次/分钟 |
| 其他接口 | 同一用户 30次/分钟 |

超出限流返回 `42901` 错误码。

---

## 九、版本控制

API路径中包含版本号 `/v1`。当发生不兼容变更时，发布新版本 `/v2`，旧版本保留至少6个月。

兼容性变更（不升版本）：
- 新增可选请求参数
- 新增响应字段
- 新增枚举值

不兼容变更（需升版本）：
- 删除或重命名字段
- 修改字段类型
- 修改接口语义
