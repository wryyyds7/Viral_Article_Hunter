## 二、用户消息触发（P0-MVP）

### 2.1 显式操作

| 操作入口 | 触发的任务 | 说明 |
|----------|-----------|------|
| 点击"采集热点" | 采集任务 | 用户选择平台+关键词 |
| 点击"上传文档" | 文件解析+分析 | 拖拽/选择文件 |
| 点击"分析" | 爆款分析 | 对单篇或批量素材 |
| 点击"改写" | 跨平台改写 | 选择素材+目标平台 |
| 点击"重试" | 重新执行失败任务 | 失败任务可重试 |

### 2.2 自然语言指令（预留）

| 用户说的话 | Agent理解 | 触发链路 |
|-----------|----------|----------|
| "帮我做一期小红书内容" | 采集→筛选→分析→改写(小红书) | 一键链路 |
| "今天有什么热点" | 查看今日采集结果 | 仅查询 |
| "把这篇改写成知乎风格" | 对指定素材改写(知乎) | 单平台改写 |

> 自然语言指令为 v2.0 能力，MVP 阶段仅预留接口，不实现 NLU 解析。

## 三、事件驱动触发（P0-MVP）

### 3.1 内部事件清单

| 事件 | 来源 | 自动触发 | 通知用户 |
|------|------|----------|----------|
| `collect.completed` | 采集模块 | 自动触发分析 | 否（等分析完） |
| `collect.partial` | 采集模块 | 自动触发分析(已有数据) | 否 |
| `collect.failed` | 采集模块 | 无 | 是："采集失败，{原因}" |
| `analyze.completed` | 分析模块 | 无 | 是："N篇分析完成" |
| `analyze.failed` | 分析模块 | 无 | 是："分析失败，{原因}" |
| `upload.parsed` | 上传模块 | 数量≥10自动触发分析 | 是 |
| `upload.parsed_below_threshold` | 上传模块 | 不自动触发 | 是："建议补到10篇" |
| `rewrite.platform_completed` | 改写模块 | 无 | 否（等全部完成） |
| `rewrite.completed` | 改写模块 | 无 | 是："改写完成" |
| `rewrite.partial` | 改写模块 | 无 | 是："N/M平台改写完成" |

### 3.2 事件总线设计

```python
# 简单的进程内事件总线（MVP阶段）
class EventBus:
    """进程内事件总线，解耦模块间依赖"""
    
    _handlers: Dict[str, List[Callable]] = {}
    
    @classmethod
    def on(cls, event: str, handler: Callable):
        """注册事件处理器"""
        cls._handlers.setdefault(event, []).append(handler)
    
    @classmethod
    async def emit(cls, event: str, data: dict):
        """触发事件，异步执行所有处理器"""
        for handler in cls._handlers.get(event, []):
            try:
                await handler(data)
            except Exception as e:
                logger.error(f"事件处理失败: {event}, 错误: {e}")

# 注册示例
EventBus.on("collect.completed", auto_trigger_analysis)
EventBus.on("upload.parsed", check_threshold_and_analyze)
EventBus.on("analyze.completed", notify_user)
```

## 四、定时任务触发（P1-MVP）

### 4.1 采集计划

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 执行频率 | cron表达式 | `0 9 * * *`（每天9点） |
| 平台列表 | 哪些平台 | 用户自定义 |
| 关键词 | 采集关键词 | 用户自定义 |
| 启用/停用 | 是否生效 | 停用 |

### 4.2 定时任务管理

```python
# APScheduler定时采集任务
scheduler.add_job(
    execute_collect_plan,
    trigger=CronTrigger.from_crontab(plan.cron_expression),
    id=f"collect_plan_{plan.id}",
    replace_existing=True,
    max_instances=1,  # 不并发执行同一计划
    coalesce=True,    # 错过的只执行一次
)
```

### 4.3 时区处理

- 所有定时任务使用用户配置的时区
- 默认 Asia/Shanghai
- cron表达式基于用户时区解析

## 六、心跳检查（P2-非MVP）

### 6.1 检查策略

| 检查对象 | 频率 | 异常条件 | 处理 |
|----------|------|----------|------|
| 采集任务 | 每5分钟 | running超过10分钟无进度更新 | 标记为failed，通知用户 |
| 分析任务 | 每3分钟 | running超过5分钟无进度更新 | 标记为failed，通知用户 |
| 改写任务 | 每3分钟 | 单平台running超过2分钟 | 标记该平台failed |
| 文件解析 | 每2分钟 | running超过5分钟无进度 | 标记该文件failed |

### 6.2 僵尸任务清理

```
每小时执行一次：
1. 查询 status=running 且 updated_at > 30分钟 的任务
2. 标记为 failed
3. 通知用户："任务超时，建议重试"
4. 记录到系统日志，用于排查
```

## 七、通知机制

### 7.1 通知方式（MVP）

| 方式 | 实现方式 | 场景 |
|------|----------|------|
| 站内实时通知 | WebSocket / SSE | 任务完成、分析结果 |
| 页面内Toast | 前端组件 | 操作反馈、错误提示 |

### 7.2 通知方式（v2.0预留）

| 方式 | 实现方式 | 场景 |
|------|----------|------|
| 邮件 | SMTP服务 | 周报、重要告警 |
| 浏览器推送 | Web Push API | 用户离线时的关键通知 |

### 7.3 通知模板

通知文案遵循《Agent人设规范》的说话风格：

| 事件 | 通知文案 |
|------|----------|
| 采集完成 | "抓到 {N} 篇热点，{M}篇热度>80 🔥" |
| 采集失败 | "采集遇到问题：{原因}，建议{建议操作}" |
| 分析完成 | "{N}篇分析完成，{M}篇值得改写" |
| 改写完成 | "{N}/{M}平台改写完毕！" |
| 改写部分失败 | "{N}平台改写完成，{M}平台失败：{原因}" |
| 上传解析完成 | "{N}篇文档解析完成，正在分析..." |
| 数量不足提醒 | "目前{N}篇，建议补到10篇再分析更准确" |

### 7.4 通知频率控制

| 规则 | 说明 |
|------|------|
| 单次操作最多1条通知 | 批量采集完成只通知1次，不逐平台播报 |
| 同类通知合并间隔5分钟 | 5分钟内多次采集完成合并为1条 |
| 用户静默期不推送 | 用户10分钟无操作不推送非紧急通知 |
| 紧急通知不受限 | LLM服务宕机等影响全局的通知立即推送 |

### 7.5 站内通知数据模型

```sql
CREATE TABLE notifications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    type VARCHAR(50) NOT NULL,      -- task_complete / alert / suggestion
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL,
    related_task_id UUID,           -- 关联的任务ID
    related_task_type VARCHAR(50),  -- collect / analyze / rewrite / upload
    is_read BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_notifications_user_unread ON notifications(user_id, is_read, created_at DESC);
```
