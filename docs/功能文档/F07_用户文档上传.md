# 功能文档：用户文档上传

| 字段 | 内容 |
|------|------|
| 所属模块 | 用户文档上传 |
| 优先级 | P0（MVP必须） |
| 文档版本 | v1.0 |

---

## 一、功能概述

允许用户将本地文档（爆文/文章/笔记原文）批量上传至系统，作为爆款分析的数据源。这是**不依赖任何外部 API 的确定性数据入口**，确保核心"分析→改写"链路在任何环境下均可运行。

系统对上传文档数量设有推荐阈值（10篇）：数量达标则自动进入分析流程；数量不足时弹窗提醒，用户确认后仍可继续分析。

---

## 二、用户故事

| 编号 | 用户故事 | 验收条件 |
|------|----------|----------|
| US-U01 | 作为用户，我想批量上传文档，以便将自己收藏的爆文素材导入系统分析 | 支持拖拽/点击上传，单次最多20个文件 |
| US-U02 | 作为用户，我想上传多种格式的文档，以便不限制我的素材来源 | 支持 TXT/MD/DOCX/PDF/HTML 五种格式 |
| US-U03 | 作为用户，我想看到上传进度，以便知道文件是否上传成功 | 每个文件显示上传/解析状态（等待/上传中/解析中/成功/失败） |
| US-U04 | 作为用户，当上传文档不足10篇时，我想得到提醒但仍可选择继续，以便在紧急情况下也能使用 | 弹窗提示"文档数量较少，分析结果可能不够准确"，提供继续/取消按钮 |
| US-U05 | 作为用户，我想在上传后直接看到分析结果，以便不用手动触发 | 上传完成且数量≥10时自动触发爆款分析，＜10时提醒确认后触发 |
| US-U06 | 作为用户，我想对上传失败的文件重新上传，以便不会因个别文件问题卡住 | 失败文件可单独重新上传 |

## 三、功能需求

### 3.1 文件上传

#### 3.1.1 上传入口与交互

| 需求项 | 要求 |
|--------|------|
| 入口位置 | 采集中心页面顶部"上传文档"Tab，以及首页快捷入口 |
| 上传方式 | 拖拽文件至上传区域，或点击选择文件 |
| 多文件 | 支持单次选择最多20个文件 |
| 单文件大小 | 最大 5MB |
| 总批量大小 | 单次上传总大小不超过 50MB |

#### 3.1.2 文件格式支持

| 格式 | 扩展名 | 解析方式 | 说明 |
|------|--------|----------|------|
| 纯文本 | `.txt` | 直接读取 | 默认 UTF-8，自动检测 GBK/GB2312 |
| Markdown | `.md` | 读取纯文本，去除标记语法 | 保留标题层级作为结构参考 |
| Word 文档 | `.docx` | python-docx 提取正文 | 仅提取正文段落，忽略图片/表格 |
| PDF | `.pdf` | PyPDF2 + pdfplumber | 优先 pdfplumber，失败回退 PyPDF2 |
| 网页 | `.html` | BeautifulSoup 提取 `<body>` 正文 | 去除导航/广告/脚本等噪音 |

> 不支持的格式：`.doc`（旧版Word）、`.rtf`、`.epub`、图片类文件（`.jpg/.png`）——在文件选择时过滤。

#### 3.1.3 文件校验

| 校验项 | 规则 | 失败处理 |
|--------|------|----------|
| 格式校验 | 检查扩展名是否在白名单内 | 拒绝上传，提示"不支持的文件格式" |
| 大小校验 | 单文件 ≤ 5MB | 拒绝上传，提示"文件超过5MB限制" |
| 内容校验 | 解析后正文长度 ≥ 50 字符 | 标记为"内容过短"，不纳入分析数量计算 |
| 重复校验 | 文件名 + 文件大小 + 前100字符MD5 比对 | 提示"文件已存在"，跳过重复文件 |
| 编码校验 | 自动检测编码，无法识别时默认 UTF-8 | 解码失败的文件标记为"编码异常" |

### 3.2 文档解析与结构化

#### 3.2.1 解析流程

```
文件上传至服务端
  → 文件格式校验
  → 按格式选择解析器（txt/md/docx/pdf/html）
  → 提取正文内容
  → 内容校验（长度≥50字符）
  → 生成结构化素材记录：
     {
       title: 文件名（去掉扩展名）或文档内首个标题,
       content: 正文纯文本,
       source_platform: "用户上传",
       source_url: null,
       author: null,
       published_at: 文件修改时间或上传时间,
       collected_at: 当前时间,
       collection_method: "upload"
     }
  → 存入素材库
```

#### 3.2.2 解析异常处理

| 异常场景 | 处理策略 |
|----------|----------|
| PDF 为扫描件（纯图片） | 标记为"无法提取文字"，提示用户上传文本版 |
| DOCX 无正文段落 | 尝试提取表格文本，仍为空则标记失败 |
| HTML 正文提取为空 | 标记失败，提示"页面无可提取正文" |
| 编码识别失败 | 尝试 GBK/GB2312/Latin-1 依次解码，全部失败则标记"编码异常" |
| 解析超时（单文件 >10秒） | 中止解析，标记为"解析超时" |

### 3.3 数量阈值与提醒机制

#### 3.3.1 阈值规则

| 条件 | 行为 |
|------|------|
| 有效文档数 ≥ 10 | 自动进入爆款分析流程，无需确认 |
| 有效文档数 < 10 且 > 0 | 弹窗提醒，用户点击"继续分析"后触发分析 |
| 有效文档数 = 0 | 提示"没有有效的文档可供分析"，不触发分析 |

#### 3.3.2 提醒弹窗

```
┌─────────────────────────────────────────┐
│  ⚠️ 文档数量较少                          │
│                                         │
│  当前有效文档仅 {n} 篇，推荐至少上传 10 篇   │
│  以获得更准确的爆款分析结果。              │
│                                         │
│  建议您补充更多文档后再进行分析。           │
│                                         │
│     [继续上传]     [仍然分析]              │
└─────────────────────────────────────────┘
```

- **继续上传**：关闭弹窗，回到上传界面，已上传文件保留
- **仍然分析**：关闭弹窗，触发爆款分析流程（与正常流程一致）

### 3.4 上传进度与结果反馈

#### 3.4.1 进度展示

每个文件独立显示状态：

| 状态 | 图标 | 说明 |
|------|------|------|
| 等待中 | ⏳ | 排队等待上传 |
| 上传中 | 📤 | 显示上传进度百分比 |
| 解析中 | ⚙️ | 服务端解析中 |
| 成功 | ✅ | 显示解析出的标题和字数 |
| 失败 | ❌ | 显示失败原因，提供[重新上传]按钮 |

#### 3.4.2 批量结果汇总

全部文件处理完成后，显示汇总信息：

```
上传完成：成功 12 篇 / 失败 2 篇 / 跳过 1 篇（重复）
有效文档 12 篇，已自动开始爆款分析 → [查看分析结果]
```

### 3.5 数据归属

| 字段 | 值 |
|------|-----|
| `source_platform` | `"用户上传"` |
| `collection_method` | `"upload"` |
| `source_url` | `null` |
| `author` | `null` |

> 上传的文档在素材库中与采集的素材统一管理，通过 `collection_method` 字段区分来源。

## 四、边界情况

| 场景 | 处理方式 |
|------|----------|
| 上传中网络中断 | 已完成上传的文件正常处理，中断的文件标记失败，可重新上传 |
| 同一文件多次上传 | 重复校验拦截，提示"文件已存在" |
| 文件内容为空 | 标记为"内容为空"，不计入有效文档数 |
| 全部文件解析失败 | 提示"没有有效的文档可供分析"，建议检查文件格式 |
| 混合格式批量上传 | 各格式独立解析，成功和失败分别统计 |
| 上传期间关闭页面 | 已上传至服务端的文件不受影响，刷新后可在素材库查看 |
| 上传大文件导致超时 | 单文件超过5MB在客户端拦截；服务端解析超时10秒中止 |

## 五、非功能需求

| 指标 | 要求 |
|------|------|
| 上传速度 | 单文件5MB在5秒内上传完成 |
| 解析速度 | 单文件解析不超过10秒 |
| 并发上传 | 支持同时处理最多5个文件的解析 |
| 文件存储 | 原始文件存对象存储，解析后纯文本存数据库 |
