## 二、核心业务流程

### 2.1 主链路：采集 → 分析 → 改写

```
[用户] 点击"热点采集" → 选择平台 + 输入关键词
    │
    ▼
POST /v1/collect/tasks          ←── 创建采集任务(collection_task)
    │                               前端: collectionApi.createTask()
    ▼
[任务队列] task_queue.submit(TaskType.COLLECT)
    │
    ▼
[Worker] CollectionService.execute_collection()
    │
    ├── get_collector("xiaohongshu") → XiaohongshuCollector (RedFox API)
    ├── get_collector("zhihu")       → ZhihuCollector (RedFox API)
    ├── get_collector("bilibili")    → BilibiliCollector (B站公开 API)
    ├── get_collector("weibo")       → WeiboCollector (微博移动端 API)
    ├── get_collector("douyin")      → DouyinCollector (抖音网页 API)
    ├── get_collector("weixin")      → WeixinCollector (搜狗微信搜索)
    ├── get_collector("toutiao")     → ToutiaoCollector (头条搜索 API)
    │
    │  如果 MEDIACRAWLER_ENABLED=true:
    │  └── 所有平台 → MediaCrawlerAdapter (浏览器自动化)
    │
    ▼
采集完成 → 文章批量写入 article 表
    │
    ▼
[EventBus] 发出 collect.completed / collect.partial 事件
    │
    ▼
[自动触发] AnalysisService.auto_analyze()
    │  → task_queue.submit(TaskType.ANALYZE)
    ▼
[Worker] AnalysisService.execute_analysis()
    │
    ├── build_analysis_prompt(title, content)  ← 加载 analysis_system.md 模板
    ├── llm_client.chat(messages, temperature=0.3, response_format=json)
    │
    ▼
[适配层] adapt_analysis_output(raw_text)
    │  1. clean_llm_output()    — 去除 Markdown 包裹
    │  2. validate_schema()     — 检查必填字段
    │  3. map_fields()          — Prompt字段 → 接口字段
    │  4. validate_business()   — 评分范围/枚举值校验
    │  5. _fill_defaults()      — 缺失字段补默认值
    │
    ▼
分析结果写入 analysis_result 表
    │
    ▼
[EventBus] 发出 analyze.completed 事件
    │
    ▼
[用户] 查看分析结果(6维度可视化) → 选择文章 → 点击"改写"
    │
    ▼
POST /v1/rewrite/tasks           ←── 创建改写任务(rewrite_task)
    │                               前端: rewriteApi.createTask()
    ▼
[任务队列] task_queue.submit(TaskType.REWRITE)
    │
    ▼
[Worker] RewriteService.execute_rewrite()
    │
    ├── 逐平台改写:
    │   ├── build_rewrite_prompt(title, content, platform, style_overrides)
    │   │   ├── 加载 rewrite_system.md 模板
    │   │   ├── 加载 data/platform_rules/{platform}.md 规则
    │   │   └── 映射 style_overrides 为自然语言
    │   │
    │   ├── llm_client.chat(temperature=0.8, response_format=json)
    │   ├── adapt_rewrite_output(raw_text, source_content)
    │   ├── calculate_similarity(source, rewrite)  ← SimHash
    │   │
    │   ├── [质量自检] build_quality_check_prompt()
    │   │   └── llm_client.chat(temperature=0.2) → quality_score
    │   │
    │   └── 写入 rewrite_result 表
    │
    ▼
每平台完成 → [EventBus] rewrite.platform_completed
    │
    ▼
全部完成 → [EventBus] rewrite.completed / rewrite.partial
    │
    ▼
[前端] SSE 监听: EventSource(/v1/rewrite/tasks/{id}/stream)
    │  ├── event: result  → 单平台结果推送
    │  ├── event: done    → 全部完成
    │  ├── event: heartbeat → 心跳
    │  └── event: timeout → 超时
    │
    ▼
[用户] 查看/复制改写结果
```

### 2.2 辅链路：上传 → 分析 → 改写

```
[用户] 点击"文档上传" → 拖拽/选择文件(TXT/MD/DOCX/PDF/HTML)
    │
    ▼
POST /v1/upload/files (multipart/form-data)
    │  前端: uploadApi.uploadFiles(files) ← FormData
    ▼
[UploadService.create_batch()]
    │
    ├── 逐文件解析:
    │   ├── get_parser(format) → BaseParser 子类
    │   ├── txt/md  → TxtParser (读取全文, 提取首行标题)
    │   ├── docx    → DocxParser (python-docx 提取段落)
    │   ├── pdf     → PdfParser (PyPDF2 提取文本)
    │   └── html    → HtmlParser (BeautifulSoup 去标签)
    │
    ├── 解析成功 → 创建 article(collection_method='upload')
    │             → upload_file.status='success'
    │
    └── 解析失败 → upload_file.status='failed'
    │
    ▼
[阈值判断] success_count >= UPLOAD_THRESHOLD(10)?
    │
    ├── 是 → threshold_met=true
    │   └── [EventBus] upload.parsed → 自动触发分析
    │
    └── 否 → threshold_met=false
        └── [EventBus] upload.parsed_below_threshold
            → 前端提示"建议补到10篇"
    │
    ▼
分析 → 改写（同主链路）
```

### 2.4 数据看板流程

```

    │
    ▼

    │

    │   ├── total_articles: COUNT(article WHERE user_id)
    │   ├── total_analyses: COUNT(analysis_result JOIN article)
    │   └── total_rewrites: COUNT(rewrite_task WHERE user_id)

    │   └── AVG(analysis_result.hotness_score.score)
    │
    ├── 平台分布
    │   └── GROUP BY article.source_platform → count
    │
    ├── 采集趋势(按天)
    │   └── GROUP BY date(article.created_at) → count
    │
    └── 热门标签 TOP10
        └── 遍历 article.tags → 统计频次
```

## 四、认证流程

```
注册：POST /v1/auth/register
  ├── 前端: authApi.register({username, email, password})
  ├── 校验: username(3-50位字母数字下划线) + EmailStr + password(≥6位)
  ├── 检查唯一性(username + email)
  ├── bcrypt 哈希密码
  ├── 首个用户 → role='admin', 其余 → role='user'
  ├── 创建 user_quota 默认配额
  └── 返回: {access_token, token_type, expires_in, user}

登录：POST /v1/auth/login
  ├── 前端: authApi.login({username, password})
  ├── 支持用户名或邮箱登录
  ├── bcrypt 验证密码
  ├── 检查 status != 'banned'
  └── 返回: {access_token, token_type, expires_in, user}

获取当前用户: GET /v1/auth/me
  ├── 前端: authApi.getProfile()
  ├── 请求头: Authorization: Bearer <token>
  └── JWT 解析 → 注入 User 对象

修改密码: PUT /v1/auth/password
  ├── 前端: authApi.changePassword({old_password, new_password})
  ├── 验证旧密码
  └── 更新 bcrypt 哈希

前端 Token 管理:
  ├── 登录/注册成功 → setAuthToken(token) → localStorage 存储
  ├── 每次 API 请求 → apiFetch() 自动注入 Authorization header
  └── 退出登录 → setAuthToken(null) → 清除 localStorage
```

## 五、事件驱动流程

```
应用启动 (main.py lifespan)
    │
    ├── 注册 EventBus 事件处理器
    │
    ├── 启动任务队列 Worker (5个协程)
    │
    └── 启动定时任务调度器 (APScheduler)
        ├── 每日 00:00 → 重置所有用户配额
        ├── 每日 09:00 → 检测 API Key 过期
        └── 每 30 分钟 → 数据库健康检查

事件链路:
─────────────────────────────────────────────────────────
采集完成          → EventBus.emit(collect.completed)
  └→ AnalysisService.auto_analyze() → 提交分析任务到队列

采集部分完成      → EventBus.emit(collect.partial)
  └→ AnalysisService.auto_analyze() → 提交分析任务到队列

上传解析完成(≥10) → EventBus.emit(upload.parsed)
  └→ AnalysisService.auto_analyze() → 提交分析任务到队列

上传解析完成(<10) → EventBus.emit(upload.parsed_below_threshold)
  └→ (前端提示用户补充文档)

分析完成          → EventBus.emit(analyze.completed)
  └→ (预留: 通知用户)

分析失败          → EventBus.emit(analyze.failed)
  └→ (预留: 通知用户)

单平台改写完成    → EventBus.emit(rewrite.platform_completed)
  └→ (预留: SSE 推送)

改写全部完成      → EventBus.emit(rewrite.completed)
  └→ (预留: 通知用户)
─────────────────────────────────────────────────────────
```

## 七、降级流程

```
LLM 服务正常
    ├── 分析: LLM 6维分析(热度/情绪/标题公式/结构/Top3基因/平台适配)
    └── 改写: LLM + 平台规则 + 质量自检(4维评分)

LLM 超时/格式错误
    ├── 分析: 适配层补全默认值(hotness_score={level:C, score:50, factors:[]})
    └── 改写: 单平台失败 → 跳过, 其余继续

LLM 完全不可用
    ├── 采集: 正常运行(不依赖LLM)
    ├── 分析: LLM 调用失败 → EventBus.emit(analyze.failed) → 跳过
    ├── 改写: LLM 调用失败 → 标记平台为 failed → 部分完成
    └── 上传: 正常运行(不依赖LLM)

采集源不可用
    ├── RedFox API 未配置 → 小红书/知乎返回空结果
    ├── B站 API 风控 → 返回空, 可选配置 SESSDATA
    ├── 抖音 API 风控 → 返回空, 建议启用 MediaCrawler
    └── 其他平台 → 降级返回空, 不影响其他平台采集
```

## 八、配额与限流流程

```
请求进入
    │
    ▼
[全局限流] rate_limit 中间件 → 滑动窗口计数(进程内)
    │   采集: 5次/分钟, 上传: 5次/分钟
    │   分析: 10次/分钟, 改写: 3次/分钟
    │   管理后台: 30次/分钟
    │
    ▼ 通过
[认证] get_current_user → 解析 JWT Token
    │
    ▼ 通过
[权限] admin_only(仅admin路由) → 校验 role == 'admin'
    │
    ▼ 通过
[配额] check_quota(resource) → 查询 user_quota
    │   检查 used_xxx < daily_xxx_limit
    │   超限 → QuotaExceededError(429)
    │   跨日 → 自动重置 used 计数
    │
    ▼ 通过
[业务逻辑] Service 层执行

定时重置:
    └── APScheduler 每天 00:00 → UPDATE user_quota SET used_xxx = 0
```
